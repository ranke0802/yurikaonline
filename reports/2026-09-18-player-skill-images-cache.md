# 플레이어 스킬 이미지 및 리소스 캐시 개선

- 빌드: `0.02.116`
- 생성 방식: 내장 `image_gen`으로 투명 PNG 4종 생성 → Sharp로 4×4 프레임 정렬·여백 처리 → WebP 압축. 외부 이미지 서비스에 런타임 의존하지 않는다.
- 최종 이미지: `assets/resource/effects/player-skills/{fireball,missile,lightning,barrier}.webp`
- 최종 생성 프롬프트 전체: [generation-prompts.json](../assets/resource/effects/player-skills/generation-prompts.json)
- 크기/용량: [manifest.json](../assets/resource/effects/player-skills/manifest.json). 각 768×768, 192px 셀 16개. 합계 **947,846바이트 / 약 926KiB**. 색상 변형 파일을 추가로 다운로드하지 않는다.
- [실제 렌더러 미리보기](asset-qa/player-skills/preview.html), [검증 화면](asset-qa/player-skills/preview.png). HTML은 프로젝트 HTTP 서버에서 열면 애니메이션과 일시정지가 동작한다.

## 적용

- 파이어볼: 8프레임 비행, 경로를 따라 남는 잔상, 8프레임 점화·폭발·충격파·잔불. 충돌 좌표에 밝은 머리 부분을 맞추고 속도 벡터로 회전한다.
- 매직 미사일: 8프레임 비행과 궤적, 8프레임 마력 파편 타격. 기존 번개 선과 별개의 이미지로 표현한다.
- 체인 라이트닝: 8프레임 방전, 대상 끝점의 타격 4프레임. 긴 연결은 최대 4구간으로 나누며 시작점과 끝점을 유지한다.
- 배리어: 생성 4프레임, 유지 8프레임, 해제 4프레임. 로컬/원격 플레이어가 같은 렌더러를 사용한다.
- 마법진: 번개 시트의 마지막 4프레임을 바닥 투영 형태로 재사용한다.
- 푸른 화염·황금 미사일·붉은 번개: 초기 로딩에서 색상 변형 캔버스를 한 번 생성해 재사용한다.
- 기본 4장과 색상 변형 3장의 RGBA 표면은 약 15.75MiB이다. 매 프레임 이미지 생성, 네트워크 요청, 캔버스 필터를 실행하지 않는다. 저전력 모드에서는 잔상 개수를 줄인다.
- 피해량·판정 범위·이동 로직은 유지한다. 기존 도형 렌더링은 이미지 초기 로드 실패 시 대체 화면으로만 사용한다.

## 리소스 수명

- 게임 루프 시작 전에 플레이어 및 몬스터 스킬 시트를 다운로드·디코딩한다. 이모트와 아이템 아이콘도 초기 로딩에서 준비한다.
- 공통 `ResourceManager`가 동일 URL의 동시 요청을 합치고, 이미지 객체·JSON·텍스트를 메모리에 저장한다. 캐릭터 및 몬스터의 개별 로더도 이를 사용한다.
- 시간값을 붙여 매번 달라지던 URL을 제거했다. 이모트 선택기·채팅·아이템 UI의 이미지 URL도 동일 빌드 주소로 통일했다. 업데이트 내역과 이모트 목록의 직접 반복 fetch를 제거했다.
- JSON/텍스트는 HTTP 캐시를 사용하며, PWA는 현재 빌드 버전의 정적 자산을 Cache Storage에서 우선 반환한다. 빌드가 바뀌면 URL과 캐시도 바뀐다. 버전 확인·로그인·실시간 게임 데이터에는 정적 자산 캐시를 적용하지 않는다.
- 아직 방문하지 않은 지역의 지도·몬스터 등은 기존의 첫 사용 로딩 방식을 유지하고, 이후 받은 리소스를 재사용한다. 비활성 `main.old.js` 전용 모듈은 현행 실행 경로에 포함되지 않는다.
- 브라우저 데이터 삭제나 저장 공간 회수 이후에는 다시 다운로드가 필요하다. 네트워크 실패를 프레임마다 재시도하지 않는다.

## 검증

- `npm run validate` 통과: 월드·콘텐츠·UI·런타임·투사체·돌진 방향·튜토리얼 관련 기존 검증, 신규 리소스 검증 5건 포함.
- Chrome Playwright **12건 통과**: 기존 로그인/레이아웃/튜토리얼/몬스터 방향 회귀 테스트 포함.
- 신규 실제 브라우저 검증: 시트별 최초 요청 1회(총 4회), 여러 번의 preload 호출과 120회 장면 렌더링·240회 실제 투사체 렌더링 이후 추가 요청 0회. 연결을 끊고 `fetch`, `Image`, `createElement`를 실패시키는 상태에서도 렌더링 성공.
- 새로고침 후 새 ResourceManager로 오프라인 이미지·이모트 JSON·README 로딩 성공. JSON과 텍스트 응답이 실제 서비스 워커에서 제공됨을 확인.
- 투명도, 인접 셀 경계, 1MiB 이내 용량, 실패 후 명시적 재시도, 새 버전 URL 분리도 자동 검증했다. 프레임 8 아래에 섞인 다음 행의 불꽃 조각은 패킹 시 제외했다.
- 로컬 macOS 검증은 설치된 Chrome과 `python3`를 사용하는 임시 Playwright 설정으로 실행했다. 운영 Firebase 데이터 쓰기를 차단한 상태로 부팅을 검증했다. 운영 배포는 실행하지 않았다.

## 재패킹

`node scripts/pack-player-skill-vfx.mjs <fireball.png> <missile.png> <lightning.png> <barrier.png>`

PNG 원본은 생성 도구 저장 위치에 보관하고, 게임이 참조하는 최종 WebP와 프롬프트/메타데이터는 프로젝트 안에 저장했다.
