# 현재 브랜치 안정화 우선순위

## 범위

- 현재 브랜치를 실사용자 대상 안정화 브랜치로 정의한다.
- 현재 이용자들이 쓰고 있는 멀티플레이 및 플레이 가능 상태를 유지한다.
- 큰 제품 방향 전환은 추후 신규 브랜치로 미룬다.

## 브랜치 역할

- 현재 브랜치
  - 안정성 확보
  - 버그 수정
  - 동기화 정확도 개선
  - RTDB 비용 통제
  - 배포 및 캐시 안정화
  - 모바일/PC 사용성 마감
- 미래 브랜치
  - 싱글플레이 중심 내러티브 재구성
  - 시나리오 기반 단계 재설계
  - 멀티플레이 범위 축소 또는 제거

## 운영 원칙

1. 현재 브랜치에서는 큰 방향 전환을 하지 않는다.
2. 실사용자 문제를 직접 해결하지 않는 위험한 리팩터링은 하지 않는다.
3. 플래그, 국소 수정, 되돌리기 쉬운 변경을 우선한다.
4. 기능 확장 속도보다 회귀 감소를 더 중요하게 본다.

## 우선순위

### P0: 서비스 신뢰성

- 멀티플레이 동기화는 현재 이용자가 신뢰할 수 있는 수준까지 안정화되어야 한다.
- RTDB 사용량 급증은 지속 가능한 수준으로 낮춰야 한다.
- 크래시, 소프트락, 빈 화면 회귀가 없어야 한다.
- 저장, 프로필, 인벤토리, 퀘스트 데이터는 안전하게 유지되어야 한다.
- 버전 업데이트와 캐시 무효화는 실제 사용자 기기에 안정적으로 적용되어야 한다.

수용 기준 예시:

- 2클라이언트 플레이에서 몬스터 위치나 상태가 자주 어긋나지 않는다.
- 일반 플레이 중 중복 hot path write 때문에 RTDB 사용량이 급등하지 않는다.
- 새로고침 또는 재접속 이후 구버전/신버전 에셋이 섞여 남지 않는다.

### P1: 플레이 가능성과 공정성

- 호스트와 게스트의 전투 결과가 최대한 일치해야 한다.
- 몬스터 생성, 사망, 드랍, 보상은 authoritative하고 일관되게 처리되어야 한다.
- 모바일과 PC 조작은 완성된 느낌으로 예측 가능해야 한다.
- 튜토리얼은 실제 UI를 가리지 않으면서 현재 UX를 정확히 안내해야 한다.

수용 기준 예시:

- 파이어볼, 매직 미사일, 실드, 몬스터 공격이 호스트/게스트 모두에서 비슷하게 동작한다.
- 터치, 마우스, 키보드 입력 흐름이 서로 충돌하지 않는다.
- 모바일 세로, 모바일 가로, 데스크톱에서 튜토리얼 단계를 레이아웃 마찰 없이 진행할 수 있다.

### P2: 저위험 품질 개선

- 인벤토리, 스킬 상세, 미니맵, HUD 가독성 개선
- 성능 및 텔레메트리 가시성 개선
- 게임 규칙을 바꾸지 않는 소규모 문구/콘텐츠 수정

## 명시적으로 미루는 항목

- 현재 브랜치에서 멀티플레이 제거
- RTDB 외 별도 실시간 전송 구조로 전면 전환
- 새로운 시나리오 흐름에 맞춘 스토리 중심 재구성
- 실사용자 버그와 무관한 대규모 전투 시스템 재설계
- 명확한 사용자 필요 없이 진행하는 대형 저장 스키마 변경

## 권장 작업 순서

1. 멀티플레이 정확성
   - 플레이어 가시성
   - 몬스터 authoritative 처리
   - 호스트/게스트 데미지 일치
   - 입장/재입장 안정화

2. RTDB 비용 통제
   - presence/move 중복 hot path 제거
   - join keyframe full sync 트리거 축소
   - 서비스 안정성을 해치지 않는 범위에서만 플레이어 AOI 전달 추가

3. 크래시 및 배포 안정성
   - 방어적 null 가드
   - stale event 순서 꼬임 방지
   - 캐시/버전 검증

4. 입력 및 튜토리얼 마감
   - 전투 입력의 PC/모바일 동등성 마무리
   - 튜토리얼이 실제 UI 상태와 배치를 반영하도록 정리

5. 저위험 UX 폴리시
   - P0/P1이 잠잠해진 뒤 진행

## 검증 기준

- 위험한 변경마다 반복 가능한 최소 수동 테스트 매트릭스를 유지한다.
  - 싱글플레이 세션
  - 2클라이언트 대기 상태 가시성
  - 2클라이언트 전투 및 몬스터 스폰 동기화
  - 새로고침 / 재접속
  - 모바일 세로
  - 모바일 가로
  - 데스크톱

## 트레이드오프

- 이 접근은 현재 브랜치에서 새로운 기능 추가 속도를 늦춘다.
- 대신 기존 이용자를 보호하고, 추후 재설계 브랜치를 별도로 준비하는 동안에도 현재 브랜치를 배포 가능한 상태로 유지할 수 있다.

## 결론

- 현재 브랜치는 실사용자용 안정화 브랜치로 다룬다.
- 이미 존재하는 기능을 끝까지 마무리하고 단단하게 만든다.
- 시나리오 중심 싱글플레이 전환은 준비가 되었을 때 새 브랜치에서 진행한다.
