# v0.01.101 / v0.01.102 테스트 케이스

## 1. 문서 목적

- `v0.01.101`과 `v0.01.102`에 반영된 멀티 안정화, 체인 라이트닝 이동, 저장 경량화 관련 변경을 수동 QA 기준으로 검증한다.
- 실제 라이브 유저가 겪을 수 있는 멀티플레이 회귀를 우선적으로 재현하고 확인한다.
- RTDB 사용량이 여전히 높은 상태이므로, 기능 검증과 함께 측정 데이터도 같이 수집한다.

## 2. 대상 버전

- `v0.01.101`
  - 커밋: `22a9e4f`
  - 범위: 멀티 visibility 안정화, 보스 소환 authoritative 처리, 몬스터 오프스크린 AI, HP 회복 동기화, 저장 경량화 1차, 오토 체인 라이트닝 이동
- `v0.01.102`
  - 커밋: `0918f59`
  - 범위: 수동 공격 버튼 홀드 중 체인 라이트닝 채널링 이동 허용

## 3. 공통 테스트 환경

- 클라이언트 2대 이상
- 권장 조합
  - PC 크롬 2창
  - 모바일 1대 + PC 1대
- 같은 필드에서 만날 수 있는 계정 2개 이상
- 퀘스트 `대왕 슬라임 소환` 가능 계정 1개 이상
- Firebase RTDB 사용량 콘솔 확인 가능 상태

## 4. 공통 기록 항목

- 테스트 버전
- 테스트 시각
- 호스트 계정 / 게스트 계정
- 재현 절차
- 실제 결과
- 기대 결과 충족 여부
- 스크린샷 또는 영상 유무
- Firebase 사용량 스크린샷 유무

## 5. v0.01.101 기능 테스트 케이스

### TC-101-01. 정지 상태 플레이어 visibility 유지

- 목적: 가만히 있을 때 상대 플레이어가 사라졌다 나타나는지 확인
- 사전 조건: 같은 필드에 호스트 1명, 게스트 1명 접속
- 절차
  1. 두 캐릭터를 같은 화면 안에 위치시킨다.
  2. 두 클라이언트 모두 30초 이상 아무 입력 없이 대기한다.
- 기대 결과
  - 서로의 캐릭터가 30초 동안 계속 보인다.
  - 상대 캐릭터가 깜빡이거나 완전히 사라지지 않는다.

### TC-101-02. 게스트 이동 중 호스트 visibility 유지

- 목적: 게스트만 계속 이동할 때 호스트가 보였다 사라지는지 확인
- 사전 조건: 같은 필드에 호스트 1명, 게스트 1명 접속
- 절차
  1. 호스트는 정지 상태를 유지한다.
  2. 게스트는 20초 이상 같은 화면 안에서 계속 이동한다.
- 기대 결과
  - 호스트 화면에서 게스트가 연속적으로 보인다.
  - 게스트가 몇 초 간격으로 사라졌다 다시 나타나지 않는다.

### TC-101-03. 호스트 이동 중 게스트 visibility 유지

- 목적: 호스트만 이동할 때 게스트 화면에서 호스트가 사라지는지 확인
- 사전 조건: 같은 필드에 호스트 1명, 게스트 1명 접속
- 절차
  1. 게스트는 정지 상태를 유지한다.
  2. 호스트는 20초 이상 같은 화면 안에서 계속 이동한다.
- 기대 결과
  - 게스트 화면에서 호스트가 계속 보인다.
  - 이동 중 위치 보간은 있더라도 완전 소실은 없어야 한다.

### TC-101-04. 게스트 퀘스트 보스 소환 동기화

- 목적: 게스트가 소환한 대왕 슬라임이 호스트에게도 보이는지 확인
- 사전 조건: 게스트 계정이 `대왕 슬라임 소환` 퀘스트 보상을 받을 수 있어야 함
- 절차
  1. 호스트와 게스트를 같은 필드에 둔다.
  2. 게스트가 퀘스트 보상으로 대왕 슬라임을 소환한다.
- 기대 결과
  - 호스트와 게스트 모두 대왕 슬라임을 본다.
  - 양쪽 모두 같은 위치 근처에 소환된 것으로 보인다.

### TC-101-05. 대왕 슬라임 이동 및 분열 처리

- 목적: 대왕 슬라임의 AI와 사망 후 분열이 authoritative하게 동작하는지 확인
- 사전 조건: `TC-101-04` 직후 또는 대왕 슬라임이 존재하는 상태
- 절차
  1. 대왕 슬라임을 일정 거리에서 관찰한다.
  2. 보스가 이동하는지 확인한다.
  3. 보스를 처치한다.
- 기대 결과
  - 대왕 슬라임이 멈춰 서 있지 않고 정상적으로 움직인다.
  - 사망 시 분열 슬라임이 생성된다.
  - 호스트와 게스트 모두 같은 분열 결과를 본다.

### TC-101-06. 호스트와 멀리 떨어진 게스트 주변 몬스터 AI

- 목적: 호스트 시야 밖에서도 게스트 주변 몬스터 AI가 멈추지 않는지 확인
- 사전 조건: 호스트와 게스트가 같은 필드에 있으나 충분히 멀리 떨어져 있어야 함
- 절차
  1. 게스트가 멀리 떨어진 곳에서 슬라임을 유인한다.
  2. 슬라임 돌진 조준선이 뜨는지 본다.
  3. 실제 돌진까지 이어지는지 본다.
- 기대 결과
  - 조준선만 뜨고 멈추지 않는다.
  - 슬라임이 실제로 돌진한다.

### TC-101-07. HP 회복 동기화

- 목적: HP 자연 회복과 즉시 회복이 상대 화면에도 반영되는지 확인
- 사전 조건: 같은 필드에 호스트 1명, 게스트 1명 접속
- 절차
  1. 한 플레이어가 피해를 받는다.
  2. 자연 회복을 기다린다.
  3. 가능하면 레벨업 또는 즉시 회복 상황도 만든다.
- 기대 결과
  - 상대 화면의 HP 바도 함께 차오른다.
  - 자연 회복과 즉시 회복 모두 반영된다.

### TC-101-08. 오토 체인 라이트닝 이동

- 목적: 오토 모드 체인 라이트닝 유지 중 70% 이동이 가능한지 확인
- 사전 조건: 체인 라이트닝 사용 가능 상태
- 절차
  1. 오토 공격을 켠다.
  2. 체인 라이트닝이 유지되는 상황을 만든다.
  3. 이동 입력을 준다.
- 기대 결과
  - 플레이어가 완전히 멈추지 않는다.
  - 평소보다 느리지만 이동 가능하다.
  - 체감상 기존 이동 속도의 약 70% 수준이어야 한다.

### TC-101-09. 원격 플레이어 미끄러짐 관찰

- 목적: 원격 플레이어의 보간이 과도하지 않은지 확인
- 사전 조건: 같은 필드에 호스트 1명, 게스트 1명 접속
- 절차
  1. 한 플레이어가 짧게 이동 후 멈춘다.
  2. 상대 화면에서 정지 시점의 위치를 본다.
  3. 같은 동작을 여러 번 반복한다.
- 기대 결과
  - 멈춘 뒤에도 한참 미끄러지지 않는다.
  - 약간의 보간은 있더라도 과도한 슬라이딩은 없어야 한다.

### TC-101-10. 저장 경량화 1차와 RTDB 사용량 측정

- 목적: 기능 정상 동작을 유지하면서 저장량과 다운로드량을 관찰
- 사전 조건: Firebase RTDB 사용량 화면 접근 가능
- 절차
  1. 2클라로 20분 동안 플레이한다.
  2. 사냥, 이동, 퀘스트 보상, 보스 소환을 섞어서 진행한다.
  3. 20분 종료 후 RTDB 다운로드량 스크린샷을 남긴다.
- 기대 결과
  - 인벤토리, 경험치, 골드, 퀘스트 카운트 저장이 정상이다.
  - 저장 누락 없이 플레이 진행이 된다.
  - 데이터 사용량 급증 구간이 있다면 당시 행동을 함께 기록한다.

## 6. v0.01.102 기능 테스트 케이스

### TC-102-01. 수동 체인 라이트닝 홀드 중 이동

- 목적: 수동 공격 버튼을 누른 채 체인 라이트닝 채널링 중에도 70% 이동이 가능한지 확인
- 사전 조건: 체인 라이트닝 사용 가능 상태, 오토 공격 OFF
- 절차
  1. 수동 공격 버튼을 누른 채 체인 라이트닝을 유지한다.
  2. 버튼을 누른 상태로 이동 입력을 준다.
- 기대 결과
  - 플레이어가 완전히 멈추지 않는다.
  - 이동 속도는 일반 이동보다 느리며 체감상 약 70% 수준이다.

### TC-102-02. 수동 체인 라이트닝 이동 중 방향 전환

- 목적: 채널링 중 이동 방향 전환이 부드럽게 되는지 확인
- 사전 조건: `TC-102-01`과 동일
- 절차
  1. 수동 공격 버튼을 누른 채 전진한다.
  2. 좌우 또는 대각선 방향으로 여러 번 방향을 바꾼다.
- 기대 결과
  - 채널링이 즉시 끊기지 않는다.
  - 입력 방향대로 저속 이동이 계속된다.

### TC-102-03. 수동 체인 라이트닝 종료 후 이동 속도 복구

- 목적: 버튼을 떼면 일반 이동 속도로 정상 복귀하는지 확인
- 사전 조건: `TC-102-01` 직후
- 절차
  1. 수동 공격 버튼을 뗀다.
  2. 바로 다시 이동한다.
- 기대 결과
  - 채널링 이동 상태가 해제된다.
  - 이동 속도가 일반 속도로 복구된다.

### TC-102-04. 다른 스킬 캐스팅 이동 차단 유지

- 목적: 체인 라이트닝 외의 스킬은 기존처럼 이동이 막히는지 확인
- 사전 조건: 매직 미사일, 파이어볼, 실드 등 사용 가능
- 절차
  1. 각 스킬 캐스팅 중 이동 입력을 준다.
  2. 체인 라이트닝과 비교한다.
- 기대 결과
  - 체인 라이트닝 지속 채널링 외의 짧은 캐스팅은 기존처럼 이동이 제한된다.
  - 변경 범위가 다른 스킬까지 번지지 않는다.

## 9. 현재 특별 관찰 포인트

- 멀티 기능은 이전보다 안정화됐지만, RTDB 사용량은 여전히 높은 편이므로 `TC-101-10`을 매번 누적 기록하는 것이 좋다.
- `v0.01.102`는 체인 라이트닝 이동 규칙만 좁게 변경한 버전이므로, 다른 스킬 이동 규칙이 바뀌지 않았는지 반드시 같이 확인한다.
