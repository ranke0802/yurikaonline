# Yurika Online — 4인 수집형 RPG 화면 콘셉트

컨펌 원화를 중심으로 주인공 1명과 동료 3명이 함께 출전하는 가로형 모바일 UI 프로토타입입니다. v5는 갤럭시 S23(2340×1080)·아이폰 14 Pro(2556×1179), 약 19.5:9를 기본 구도로 사용합니다. 기존 게임과 원화 연구 페이지는 유지하고, 새 폴더에서 독립적으로 실행합니다.

## 실행

현재 미리보기: http://127.0.0.1:8100/?v=5

폴더의 `시작.command`를 실행한 뒤 위 주소를 열거나, 이 폴더에서 아래 명령을 실행합니다. 이미 서버가 실행 중이면 추가 실행할 필요가 없습니다.

```sh
python3 -m http.server 8100 --bind 127.0.0.1
```

같은 Wi-Fi의 휴대전화로 볼 때는 아래 명령으로 서버를 열고 `http://맥의_로컬_IP:8100/`에 접속합니다. 휴대전화는 가로로 돌려 사용합니다.

```sh
python3 -m http.server 8100 --bind 0.0.0.0
```

## 구현한 흐름

1. 네 동료의 여정이 담긴 오프닝. 하단 로딩바는 최소 1초 진행합니다. 이미지 준비가 끝나면 START가 나타나며, 터치 전에는 넘어가지 않습니다. 최초 이미지 다운로드가 느리면 1초보다 길어질 수 있습니다.
2. 달숲 야영지. 전사는 검을 정비하고, 마법사는 지도를 살펴보고, 위치는 책을 읽고, 궁수는 활을 점검합니다. 배경·4인·테이블을 개별 레이어로 구성했습니다. 캐릭터 터치 시 상단 전용 영역에 대사와 관리 버튼이 나타납니다. 바닥의 빈 지면에 4인 편성·주 메뉴·원정 출발을 띄우고, 생활 장면의 활동 위치는 캐릭터별로 유지됩니다.
3. 동료 메뉴 안의 파티 편성. 전체/공격/지원 필터로 보유 목록을 좁힐 수 있습니다. 동료 자리 선택 → 목록에서 동료 선택 → 이미 편성된 동료라면 자리 교환 → 저장. 주인공은 첫 자리에 고정되고, 중복 없이 4명을 채워야 저장할 수 있습니다. 미저장 상태에서 이동하면 계속 편성/취소/저장을 선택합니다.
4. 동료 메뉴 안의 캐릭터 관리. 컨펌 원화의 배경을 화면 전체로 이어 붙이고, 왼쪽 배경 여백에 선택 목록, 오른쪽 배경 여백에 성장·장비·스킬 패널을 띄웁니다. 성장 전후 능력치와 강화 비용을 보여주고, 레벨·무기 강화 후 수치 증가를 안내합니다. 장비·스킬은 항목을 선택하면 설명이 펼쳐집니다. 실행 버튼은 패널 하단에 고정됩니다.
5. 상점. 상점의 캐릭터와 물건이 있는 배경을 유지하고 오른쪽 빈 선반 쪽에 상품을 세로로 배치했습니다. 실물 형태의 물품 원화로 진열한 상품 선택 → 구매 확인 → 골드와 보유품 반영. 클랜. 네 동료가 보이는 전체 배경 위, 오른쪽 빈 게시판 쪽에 패널을 놓았습니다. 가입 버튼은 패널 상단에 고정했습니다. 가입 → 공지/멤버/공동 목표 확인 → 하루 한 번 기여 → 탈퇴 확인. 멤버와 공동 목표는 로컬 체험용 예시입니다.
6. 원정 준비. 지역과 4인 파티를 검토하는 출발 안내까지 연결했습니다. 실제 4인 전투는 이 콘셉트에 포함되지 않습니다.

초기 보유 캐릭터는 컨펌된 4명입니다. 현재는 세 동료의 자리를 바꾸는 편성 경험이며, 보유 동료가 늘어나면 동일한 슬롯 흐름에서 교체하도록 확장합니다. 마법사를 주인공으로 설정했습니다. 이름·역할·레벨·가격·전투력은 흐름 확인을 위한 임시 데이터입니다.

## 그림과 연출

- 기존 컨펌 원화: 마법사 v4, 전사 v4, 위치 v2, 궁수 v7. `assets/*-key.png`에 원본 그대로 복사했습니다.
- 신규 이미지: 오프닝, 대기실 배경, 네 캐릭터의 투명 대기 이미지. 기존 원화를 참조해 built-in `image_gen`으로 생성했습니다. 신규 파생 이미지는 제작용 최종 컨펌이 추가로 필요합니다.
- v2 신규 이미지: 야영지 완성 장면, 인물이 없는 배경, 네 동료와 개별 좌석, 공용 테이블, 상점 물품 3종. built-in `image_gen`으로 제작했습니다. 파생 원화는 제작용 최종 컨펌이 필요합니다.
- 초기 생성 기록은 `generation-prompts.json`, v2의 모든 프롬프트·참조·생성 및 저장 경로는 `generation-prompts-v2.json`에 있습니다.
- 추출 레이어는 CSS와 인계 JSON의 크기·위치 보정으로 합성합니다. 정밀하게 분리된 PSD나 Live2D 모델이 아닙니다.
- 상점·클랜·원정 배경은 기존 콘셉트에서 재사용했습니다.
- 크림색 패널, 금빛 강조, 어두운 버튼, 눌림·선택·터치 링과 작은 효과음을 이어받았습니다. 설정에서 움직임/소리/지원 기기의 진동을 조절합니다.
- 움직임은 PNG 레이어에 적용한 CSS 호흡·배경 이동입니다. 실제 Live2D가 아니며, Unity에서는 분리 원화와 리깅/Animator 작업이 필요합니다.

## Unity 제작 인계

`unity-handoff.json`에 화면 흐름, 고정 주인공·4인 중복 방지 규칙, 캐릭터/상점/지역 데이터, 에셋 연결을 정리했습니다. 기준 화면은 2340×1080입니다. 갤럭시 S23과 아이폰 14 Pro에서 약 19.5:9 구도를 유지하며 실제 기기는 SafeArea와 Canvas Scaler로 대응합니다. 웹은 viewport-fit=cover와 환경 안전 영역, 100dvh를 사용합니다. 안전 영역은 OS·회전·브라우저 상태에 따라 런타임에서 읽습니다.

권장 데이터 분리는 CharacterDefinition(정적 캐릭터 정의), CharacterProgress(레벨·장비), PartyState(저장 편성), PartyDraft(미저장 편성), Inventory, ClanState입니다. UI는 이 상태를 읽고 검증된 명령을 전달하도록 만듭니다. 현재 저장소 키는 `yurika.party-rpg.concept.v1`이며 기존 게임의 저장 기록과 분리됩니다.

예상 제작 과제:

- 기존 1인 전투에 4인 UI만 연결하면 타깃 선택·피해·회복·사망·카메라·입력 처리가 맞지 않습니다. 전투는 PartyBattle 인터페이스와 4인 전투 상태를 먼저 정의해야 합니다. 자동 전투/직접 조작 범위도 제작 전에 확정해야 합니다.
- 초기 4명만으로는 수집과 파티 선택의 폭이 제한됩니다. 후속 동료의 역할·상성·획득 루프를 설계하고, 보유 목록을 스크롤·필터 방식으로 확장해야 합니다.
- 전체 일러스트를 단순 변형하면 팔·얼굴·머리카락이 따로 움직이지 않습니다. 고품질 대기 연출에는 레이어 분리와 일관된 발 기준점이 필요합니다.
- 계정·구매·클랜은 현재 브라우저에만 저장되는 체험입니다. 실제 서비스에서는 서버 검증, 재화 거래의 원자성, 중복 구매 방지, 날짜 기준, 클랜 권한 처리가 필요합니다.
- 생성 원본과 이전 에셋도 보관하고 있어 배포 시 사용 에셋 선별이 필요합니다. Unity에서는 플랫폼별 텍스처 압축·해상도·Addressables 로딩 전략과 메모리 예산을 정합니다.
- 가로 휴대전화에서는 상세 패널을 스크롤할 수 있습니다. 손가락 크기에 맞는 터치 영역과 기기별 안전 영역은 실제 기기에서도 확인해야 합니다.

## 검증

`qa/validate.cjs`는 기존 프로젝트의 Playwright 설치를 이용하는 개발 검증 스크립트입니다. 런타임에는 Node.js나 Playwright가 필요하지 않습니다.

v1 검증은 `qa/`, 개편한 v2 검증과 화면 캡처는 `qa-v2/`에 있습니다. v2 검증은 `node qa-v2/validate.cjs`로 실행합니다. v2는 1440×810, 아이폰 비율 852×393, S23 비율 780×360, 주소창으로 높이가 줄어든 852×320 브라우저 및 좌우 카메라/하단 안전 영역을 가정한 시뮬레이션에서 시작 대기, 4인 투명 이미지, 편성 교환/빈 자리/저장/미저장 이동, 성장·장비 비용, 구매 취소/확정, 클랜 기여, 출전 안내, 움직임 설정, 재접속 저장과 오류 발생 여부를 확인합니다. 실제 iOS/Android 기기나 Unity 빌드를 검증한 결과는 아닙니다.

## 개편 기록과 범위

이전 배치의 코드 스냅샷은 `archive-v1/`, `archive-v2/`, `archive-v3/`에 보관했습니다. 기존 원화 연구 페이지와 원래 게임 소스는 변경하지 않았습니다. 브라우저 저장소 키를 유지하므로 기존 콘셉트의 편성·성장·구매 기록이 이어집니다. 기존 단일 캐릭터 전투에 연결하지 않았으며, 실제 4인 전투·온라인 클랜·결제·Live2D 리깅은 Unity 제작 과제입니다.


## v4 배치 기준

화면을 그림과 UI의 사각 구역으로 나누지 않습니다. 하나의 장면 위에서 인물의 얼굴·손·무기·다리가 놓인 영역을 피하고, 나머지 배경 여백에 조작을 띄웁니다. 위아래 불투명 띠와 일러스트 액자를 제거했습니다.

- 대기실: 전체 야영지 배경을 유지하고, 바닥의 빈 지면에 작은 편성 버튼·주 메뉴·출발 버튼을 띄웁니다. 네 동료와 테이블은 기존 합성 캔버스의 비율을 유지합니다. 선물·재화는 상단 빈 배경에, 대사는 위쪽의 작은 팝업에 표시합니다.
- 관리: 원화의 전체 높이를 활용합니다. 좌우로 남는 화면은 같은 배경을 부드럽게 이어 채우고 인물의 비율을 유지합니다. 편성/관리 전환과 동료 선택은 왼쪽 가장자리의 빈 배경에, 상세 패널과 주 메뉴는 오른쪽의 빈 배경에 띄웁니다.
- 상점: 위치와 마법사, 뒤쪽 동료까지 보이게 화면 위치를 맞추고 오른쪽에 상품 세 줄을 배치합니다. 낮은 화면에서도 구매 버튼이 잘리지 않도록 각 줄의 높이를 조정했습니다.
- 클랜·원정: 기존 전체 그림 위 오른쪽의 인물이 없는 벽·풍경 쪽에 게시판과 원정 준비 패널을 띄웁니다. 뒤로 가기와 제목도 상단의 인물 없는 곳에 놓습니다.
- 오프닝: 여정 원화가 화면 전체로 이어집니다. 로고·로딩·START는 왼쪽 여백에 모아 여행자들과 겹치지 않습니다.
- 컨펌 원화 네 파일의 SHA-256은 변경 전과 동일합니다. 눌림·선택·효과음·호흡 움직임과 기존 브라우저 기록도 유지합니다.

`qa-v4/validate.cjs`는 여섯 화면 크기/안전 영역 조건에서 주요 버튼과 편성·성장·장비·구매·클랜·출전 흐름을 검증합니다. `qa-v4/occlusion.cjs`는 다섯 조건에서 야영지 네 인물/테이블의 실제 투명 영역, 네 컨펌 원화의 얼굴·손·다리, 상점·클랜·원정의 동료 및 오프닝 여행자 영역과 UI의 충돌을 검사합니다. 원화 자체에서 화면 가장자리로 잘려 그려진 전경은 그대로 유지합니다. 결과 JSON과 화면 캡처는 같은 폴더에 있습니다. 실제 기기의 OS 안전 영역과 Unity 빌드는 별도 검증 대상입니다.

## 하단 메뉴 고정

v5에서는 대기실·파티 편성·캐릭터 관리·상점·클랜·원정에서 주 메뉴 바와 네 버튼이 동일한 우측 하단 좌표·크기·배열을 사용합니다. 선택 상태만 바뀌며 버튼을 누르거나 선택할 때 위치 이동·확대·축소가 발생하지 않습니다. 색상 반응과 효과음은 유지합니다. 대기실의 출발/편성 버튼은 고정 메뉴 옆의 빈 지면에 배치합니다.

`qa-v5/navigation.cjs`는 다섯 화면 크기/안전 영역 조건에서 화면 전환 전후 메뉴 바와 네 버튼의 좌표, 누름 중 크기·위치, 상세 스크롤 중 고정 여부, 버튼 접근성을 검증합니다. `qa-v5/occlusion.cjs`는 기존 캐릭터와 새 위치의 메뉴/대기실 버튼의 충돌을 검사합니다.
