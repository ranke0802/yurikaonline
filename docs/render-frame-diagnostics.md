# v0.02.169 사용자 조작형 로컬 화면 진단

기준은 remote `mmorpg_online` v168 `a0fc2274ecc54ca410ed0e28aeb4a81d517c76dc`입니다. v169는 점멸 원인을 관찰하는 도구를 추가합니다. Canvas 최초 옵션(`alpha:false, desynchronized:true`), 렌더 순서, 원화, 전투, 저장 및 권한 동작은 유지합니다. 별도의 강화 저장 후보는 포함하지 않습니다. **S23 실제 점멸 원인은 아직 확인되지 않았습니다.**

## S23 PWA에서 사용하는 3단계

1. 설정의 게임 버전이 **v0.02.169**인지 확인하고 **화면 진단 → 진단 시작 (최대 20초)**을 누릅니다.
2. 설정을 닫고 점멸이 발생하던 전투를 진행합니다. 최대 20초 후 자동 정지합니다. 필요하면 설정에 돌아와 **정지**를 누릅니다.
3. 설정 → 화면 진단에서 **JSON 복사** 또는 **JSON 다운로드**를 누르고, 원하는 곳에 직접 전달합니다. 복사 거부 시 표시되는 칸을 길게 눌러 복사하거나 다운로드를 사용합니다. **기록 지우기** 또는 새로고침으로 메모리 기록을 삭제합니다.

자동 기록·업로드·원격 서비스는 없습니다. 설정을 닫아도 기록은 계속되며 앱이 숨겨지면 정지합니다. 기존 게임 통신은 진단에 사용하지 않습니다. 진단 데이터는 페이지 메모리에만 존재하며 다운로드/복사는 사용자 동작으로만 실행됩니다. 다운로드한 파일과 클립보드는 사용자가 직접 관리합니다.

## 범위와 개인정보 배제

- `src/js/diagnostics/RenderDiagnostics.js`: 최초 context 요청/실제 scalar 옵션, 빌드 버전, 상대 렌더 시작 시각과 간격, 다섯 단계의 예상/시작/완료 카운트, 전체 프레임 완료 여부, 제한된 오류 정보만 기록합니다.
- 다섯 단계: 몬스터 렌더, 로컬 플레이어 렌더, 플레이어 HUD, 로컬 소환수/효과 ground 및 foreground. 계측된 호출에서 기대치를 만들지 않고 렌더 전 장면 상태와 독립적인 가시성 계산으로 기대 카운트를 만듭니다. 좌표는 이 계산에만 사용하고 기록하지 않습니다.
- 예상/완료는 **메서드 단계의 완료**입니다. 픽셀 표시/Android 합성/실제 화면 출력 완료를 증명하지 않습니다. 소환수 단계에는 해당 직업의 효과도 포함됩니다. 원격 플레이어 렌더는 이 최소 기록의 범위 밖입니다.
- 이름, 계정/엔티티 ID, 채팅, 좌표, 인벤토리, 저장 데이터, 토큰, 쿠키, URL, UA, 화면 이미지/영상, 원문 오류 메시지를 내보내지 않습니다. `exportJSON()`은 게임 객체를 펼치지 않고 허용 필드만 구성합니다.
- 오류는 고정 목록의 코드와 **허용된 소스 파일 경로·행·열 최대 3개**만 남깁니다. 원문 스택·함수명·origin·query·임의 파일 경로는 버립니다. 테스트에는 이름/토큰/query가 들어간 오류를 주입해 문자열이 남지 않는지 확인합니다.
- 주사율 필드는 없습니다. `gapMs`는 실제 기기 패널 Hz가 아닌 **계측된 렌더 시작 사이의 간격**입니다.

## 부하와 예외 처리

시작 전에는 렌더 훅과 프레임 버퍼가 없습니다. 시작하면 최대 20초, 2,048프레임의 고정 용량 버퍼를 사용하며 가득 차면 기록을 정지하고 명시합니다. 오류는 32개, 정제 스택은 오류당 3행, 몬스터 점검은 프레임당 512개, 훅은 16개로 제한합니다. 오류 상한 이후에는 버린 오류 개수만 셉니다. 프레임별 DOM 업데이트·Canvas readback·추가 RAF 루프는 없습니다.

정지하면 소유한 훅만 복구합니다. 다른 코드가 나중에 바꾼 메서드를 덮어쓰지 않습니다. 진단기 내부 오류는 기록을 중단하며 게임 렌더는 계속 호출합니다. **게임 오류는 같은 오류 객체를 다시 던지며 숨기거나 Canvas 상태를 수리하지 않습니다.** 전체 렌더 시도는 예외가 발생해도 분모에 남습니다.

`src/js/ui/RenderDiagnosticPanel.js`는 시작/정지/내보내기/지우기만 처리합니다. 내보내기는 정지 후에만 가능하며 복사 실패 시 읽기 전용 수동 복사 칸을 제공합니다. 대기 중인 복사가 나중에 실패해도 이미 지운 기록을 복구하지 않습니다.

## 검증

```sh
node --test scripts/validate-render-diagnostics-v169.mjs
node scripts/validate-render-diagnostics-v169-browser.cjs
node scripts/validate-render-frame-completeness-browser.cjs --mode=matrix
node scripts/validate-render-frame-negative-controls.cjs
```

기본 로컬 서버는 8100입니다. 브라우저 검사에서 `QA_BASE_URL`/`QA_OUTPUT`을 지정할 수 있습니다. UI 검사는 신선한 로컬 모드 프로필에서 외부 요청과 service worker를 차단하며 390×844 및 844×390을 사용합니다. 실제 20초 기록, 설정 닫기/전투/재진입, 수동 정지, 자동 정지, 복사 성공/거부, 파일 내용 동일성, 기록 중/복사 대기 중 지우기, 새로고침 후 무기록을 확인합니다.

최종 로컬 UI 검사: 양 방향 22개 항목 통과, page error 0, 외부 요청 0. 실제 공격 버튼 입력도 수락됐습니다. 20초 샘플은 세로 586프레임/66,197바이트, 가로 583프레임/65,851바이트였습니다. 실행 부하와 프레임 수에 따라 파일 크기는 달라집니다. 이는 데스크톱 Chromium의 모바일 화면 검사이며 S23 성능 수치가 아닙니다.

새 전체 프레임 회귀검사는 844×390/1404×648에서 20개 합성 시각 조건을 다룹니다. 모든 렌더 시도를 분모로 삼고 독립 기대 엔티티/HUD/소환수 출력과 실제 draw, 패스 완료, Canvas 상태를 검사합니다. 의도적인 예외/출력 생략/상태 누출은 각각 일반 검증기에서 종료 코드 1이어야 하며, CI 제어기는 실패 원인과 12개 시도까지 확인합니다. 테스트 주입은 제품 코드에 없습니다.

초기 Canvas A/B 실험은 별도 `--mode=ab`로 유지합니다. 옵션 변경은 격리된 브라우저의 최초 context 생성에만 적용되며 제품 설정에 토글을 추가하지 않았습니다. 이전 v168 실험 18조건/1,920프레임은 모두 통과했지만 실기기 해결 증거가 아닙니다.

배포 workflow에는 기존 전체 검사에 새 단위/UI/완전성/결함 대조군을 추가했습니다. 배포 후 두 진단 모듈의 공개 파일 해시와 실제 라이브 UI를 다시 확인합니다.

## 현재 실기기 정보

촬영 기기는 **Galaxy S23 설치 PWA**입니다. 설치 브라우저, 촬영 빌드, 실제 패널 주사율은 미확인입니다. Chrome 또는 120Hz로 추정하지 않습니다. iPhone 14 Pro는 사용자가 이후 시험할 예정이며 아직 결과가 없습니다. 원본 영상은 이 환경에서 다운로드되지 않았으므로 기존 프레임 관찰은 부모 스레드의 영상 검토에 근거합니다.
