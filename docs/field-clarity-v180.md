# v0.02.180 전투 표시와 직업 성장 안내

HP 회복 및 생명의 구슬 귀환 직후 HUD가 이전 수치를 잠시 표시하던 지연을 줄이고,
직업별 공격력 계산에 맞는 스탯을 성장 튜토리얼에서 안내한다. 겹친 적과 구분하기
어려웠던 소환수에는 소유 관계와 HP를 함께 표시한다. 캐릭터 본체는 원본 도트 의도에
맞춰 v176 이전 nearest 샘플링으로 복원한다.

## 동작과 범위

- 월드 렌더 전에 HP/MP 정수 표시, 최대치, 레벨/경험치, 위치의 구슬 슬롯 수를
  캐시와 비교한다. 달라진 표시만 기존 HUD 경로로 반영한다. 변하지 않은 프레임에서는
  DOM 조회/수정을 추가하지 않으며 기존 쿨다운·일반 HUD 주기는 유지한다.
- 마법사·위치는 지능 1당 공격력 +1, 지혜 2당 +1을 설명하고 지능 행을 안내한다.
  전사는 체력, 궁수는 순발력 행에서 +1 투자와 공격력 미리보기를 진행한다.
  상태창 스탯 도움말에도 같은 설명을 사용한다. 기존 저장 스탯을 옮기거나 초기화하지 않는다.
- 내 소환수는 청록색 `내 소환수`, 파티원의 소환수는 파란색 `아군 소환수` 이름표와
  체력바로 표시한다. 중립 소환수는 `소환수`, 적대 소유자의 소환수는 `적 소환수`다.
  소유 관계는 기존 공격 가능/파티 판정을 사용한다. 이름표는 몸체들 위의 공통 Canvas
  UI 패스에서 그려 원본 이미지나 소환수 전투 상태를 변경하지 않는다.
- 캐릭터 본체, 마법사 런타임 시트 합성의 보간을 끄고 Canvas CSS `pixelated`를
  복원한다. 프레임·발 위치·크롭·크기·DPR/해상도 제한은 유지한다.

소환의 최대 HP 80% 비용, 소환수 HP/공격력/방어력/공격 간격, 구슬 피해·회복·슬롯
계산을 바꾸지 않았다. 궁수 튜토리얼의 공격 사용 완료 조건, 모든 튜토리얼 단계 ID,
보상, 퀘스트 저장 키도 유지한다. 원본 이미지 재처리나 신규 아트는 없다.

## 검증과 재현

저장소 루트의 Node 22 환경과 8100 로컬 서버에서 실행한다.

```sh
npm run validate:field-clarity
QA_OUTPUT=/tmp/yurika-field-clarity npm run validate:field-clarity-browser
npm run validate:display-quality-browser
npm run validate:character-crispness-browser
npm run validate:class-attack-stats-browser
node scripts/validate-tutorial-stat-cancel-browser.cjs
node scripts/validate-class-tutorial-browser.cjs
node scripts/validate-gameplay-entry-browser.cjs
```

`validate:field-clarity-browser`는 PC 1280×800, 모바일 세로 393×852, 가로 852×393의
네 직업을 확인한다. 초기 이동/공격 단계만 로컬 테스트 상태로 건너뛰고, 스탯 미리보기,
저장 취소/확정, 스킬 강화, 튜토리얼 종료, 야영지 복귀, 새로고침·재진입은 실제 클릭/탭을
사용한다. 다른 직업의 기존 프로필 보존과 전사/궁수의 기존 지능 수치 보존도 확인한다.

위치 검증은 별도 Lv.7 스킬과 고정 표적을 사용한다. 6회 입력에서 동시 최대 4구체,
4회 × 3 회복(HP 10→22), 모든 렌더 프레임에서 HP/구슬 HUD 일치, 정지 상태 120회
동기화의 DOM 변경 0건을 검사한다. 실제 소환 입력의 80% HP 소모와 소환수 초기
HP 50/공격력 1/방어력 1/간격 3초를 검사하고, 원격 아군 렌더 상태를 구성해 적과
겹친 소환수 이름표를 캡처한다. 운영 멀티플레이 테스트는 아니다.

전체 정적 검증 명령은 `.github/workflows/firebase-hosting-merge.yml`에 유지한다.
이번 로컬 실행에서 881개 테스트와 192개 액션 셀 검사가 통과했다. 이미지 586개의
SHA-256 및 전투 계산 파일 5개가 작업 전과 동일하다. 선명도 비교의 9,216개 본체
샘플과 v176 이전 픽셀 일치 근거는 [선명도 검토](character-crispness-local-review.md)에 있다.
새 성장/HUD/소환수 검증 12개 조합, 실제 월드 표시 16개 조합, 공격력 저장/전투 8개
조합 및 기존 스탯 취소·직업 튜토리얼·첫 모험 실제 입력 회귀 검증이 모두 통과했다.
이번 통합 코드의 9,216개 본체 샘플도 v176 이전 픽셀/좌표와 전부 일치했다.
프레임 완전성 검사는 공통 UI 단계의 소환수 이름표 1회와 체력바 2회 그리기를
각 프레임에서 요구한다. 예전 Bridge 내부 체력바 계측을 새 위치에 맞추고,
체력바만 고의로 누락했을 때 실패하는 대조 검사를 추가했다. 기존 예외·몸체 누락·
Canvas 상태 누수 대조 검사도 유지한다.

새 검증은 CI 배포 전 및 Hosting 배포 후에도 실행한다. 배포 후 검증은
`QA_BASE_URL=https://yurika-online.web.app`을 지정하지만 `?local=1`의 독립 프로필과
동일 출처 요청만 사용하며 운영 계정·DB를 변경하지 않는다. 배포 자산 검증에는 새
성장 안내 및 소환수 UI 모듈의 원본 해시도 포함한다.

로컬 로그·원본 화면·자산 대조는 `/workspace/yurika-v180/`에 보관한다. 실제 휴대폰,
WebKit/Firefox, 운영 파티/PvP, 후반 밸런스·장시간 다수 개체 스트레스는 이번 검증 범위에
포함하지 않는다. 이름표끼리 겹치는 모든 군집 상황까지 해결하는 배치 알고리즘은 추가하지 않았다.
