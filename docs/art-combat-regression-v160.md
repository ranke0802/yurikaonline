# 원화 복구와 전투 연속성 v0.02.160

v159에서 플레이용 스프라이트를 원화 화면에도 연결한 것은 잘못된 변경이었습니다. CampScene의 공통 art resolver를 v158의 `party-rpg-concept/assets/`로 복구합니다. 대기실 인물, 캐릭터 관리의 직업별 key art와 idle 초상화가 원래 그림을 사용합니다. 인게임 플레이어 몸체·HUD·친구 초상화의 승인 스프라이트는 유지합니다. 원본 및 파생 파일은 삭제하지 않습니다. 로딩 화면과 PWA 이미지는 변경하지 않습니다.

## 재현 근거

v158→v159의 Monster, 공용 Sprite, MonsterManager 코드와 기존 몬스터 자산 매핑은 동일했습니다. 신규 플레이어의 256셀·6프레임 계약을 몬스터에 적용하는 경로는 없었습니다.

로컬 Chromium 실제 전투에서 일반 몬스터 4종과 보스 2종의 몸체 렌더 2,497회를 측정했습니다. 누락·투명화·빈 atlas 셀은 0회였습니다. 이는 사용자 환경의 모든 깜빡임을 재현했다는 의미는 아닙니다.

생산용 takeDamage 진입점에 150ms 간격의 반복 피격을 주입한 실제 게임 루프에서는 전역 hitstop 254회, 카메라 shake 286회가 발생했고, 403개 telemetry 프레임 중 121개가 hitstop으로 업데이트를 건너뛰었습니다. 기존 치명타 피드백은 몬스터 피격 시 60ms, 플레이어 피격 시 80ms 동안 전체 시뮬레이션을 정지했습니다. 매 타격의 카메라 흔들림도 화면 전체를 이동시켰습니다.

## 최소 수정

일반 피격에서 전역 hitstop과 camera shake 호출을 제거했습니다. HP·피해·치명타 판정·상태·타격 숫자·음향·스킬 효과·쿨다운은 변경하지 않습니다. 보스 사망 연출은 유지합니다. 동일 6종 반복 피격 조건에서 수정 후 몸체 렌더 2,563회, telemetry 449프레임 중 전역 정지/흔들림/빈 몸체는 모두 0회였습니다.

`validate-combat-continuity-v160-browser.cjs`는 기존 원화 URL의 실제 DOM 연결, 6종 몬스터 및 위치의 실제 소환수 3종, 걷기·피격·native skill 중 연속 렌더와 12장 화면 캡처, alpha·source cell·재로드·전역 정지를 검사합니다. 기존 저장·전투·모바일 입력·로딩·PWA 회귀도 배포 CI에서 실행합니다.

## 검증 한계

실제 게임 update/render와 입력을 사용하지만 계정·몬스터 배치는 격리된 로컬 fixture입니다. 물리 Android/GPU, 사용자의 정확한 지역·몬스터, 실제 다중 계정 접속에서의 모든 깜빡임은 아직 확인하지 못했습니다. 확인한 전역 정지·흔들림 원인을 수정했으며, 별도의 몸체 소실 원인을 추정해 변경하지 않았습니다.
