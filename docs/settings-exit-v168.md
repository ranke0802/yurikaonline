# v0.02.168 — 설정 종료 확인의 뒤로가기 취소

설정의 게임 종료 확인창에서 브라우저 뒤로가기 후 취소하면 종료 버튼을 다시 사용할 수 없었다. 기존 확인 콜백이 새 브라우저 종료 콜백으로 교체되어 `gameExitConfirmPending` 해제가 누락됐다. v167에서는 390×844·844×390 양쪽에서 설정 재개방과 야영지 왕복 후에도 재현됐다.

`UIManager.handleBrowserBackPopState`에서 열려 있는 설정 종료 확인은 기존 콜백을 보관하고 창을 닫은 뒤 `false`로 한 번 호출한다. 뒤로가기 자체는 저장이나 종료를 실행하지 않는다. 인벤토리 확인창 우선 처리와 확인창 없는 필드 뒤로가기, 실제 저장·flush·씬 전환 코드는 변경하지 않았다.

검증:

- `node --test scripts/validate-settings-exit-v168.mjs`: 원래 코드 8개 중 3개 실패, 수정 후 8개 통과. 취소·중복·별도 브라우저 종료, 정상 저장 옵션·순서와 실패 시 필드 유지 확인.
- `node scripts/validate-settings-exit-v168-browser.cjs`: 390×844·844×390의 18개 경로. 취소/Esc/뒤로/회전/중복 입력/설정 재개방/저장 실패·재시도/지연 저장·야영지 왕복을 실제 DOM·history 입력으로 확인. 취소 시 저장 0회, 반복 확인 시 콜백·저장 1회. 성공 경로는 격리 로컬 어댑터로 실제 저장하고 가방 내용 보존과 save→flush→camp 순서를 확인.
- CI에서 위 단위·브라우저 검사를 기존 검증에 추가하고, 배포 후에도 `QA_BASE_URL=https://yurika-online.web.app`의 격리 `?local=1` 프로필로 같은 18개 경로를 실행한다.
- v167 진단의 144개 기록 중 적용 가능한 136개를 별도 로컬 하니스로 회귀한다. 제외한 8개는 기존 결함의 중복 독립 재현 2개(신규 브라우저 검사로 대체), 합성 blur/hidden 드래그 잔류 4개, 실제 창 이탈을 만들지 못한 headless 탭 전환 2개다.

가상 프로필과 localhost/배포 사이트의 로컬 모드만 사용한다. 운영 계정·운영 저장·아이템 작업은 수행하지 않는다. 합성 blur 드래그 잔류는 이 수정에 포함하지 않았으며 실기기 앱 전환은 미검증이다. 실제기기 점멸도 해결로 주장하지 않는다. 원화·스프라이트·게임 규칙·저장 스키마·입력 크기·디자인은 변경하지 않았다.
