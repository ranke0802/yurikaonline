# v0.02.176 HUD 크기와 캐릭터 출력

비교 기준은 `76943cfd23211a5c7f6b1af24fb1bc300d443474`이다. 모든 브라우저 검증은 loopback의 `?local=1`, 새 격리 프로필, 외부 요청 차단 상태에서 실행했다.

## 변경 이유와 범위

모바일 세로 기본 배치에서 채팅 메시지의 CSS 글꼴은 12px이지만 부모의 0.55 배율을 적용하면 실제 표시 크기는 6.6px이다. 기존 좌측 HP/MP·퀘스트 글자는 실제 11px이어서 채팅보다 컸다. 이제 메시지와 부모 요소의 실제 배율을 읽어 좌측 자원·레벨·퀘스트·야영지 복귀 글자를 맞춘다. PC에서 이미 작은 항목은 채팅 크기 이하로 유지한다. 버튼의 기존 터치 영역과 저장한 배치는 유지하고, 긴 수치와 퀘스트 문장은 줄바꿈한다.

캐릭터의 256px 원본 프레임은 기본 화면에서 약 84px(모바일), 96px(PC)로 표시된다. 이 축소와 마법사 런타임 atlas 합성에서 최근접 샘플링을 강제해 외곽선·얼굴의 세부가 거칠어졌다. 모바일에서는 제한된 Canvas DPR을 화면 DPR로 확대할 때 CSS `pixelated`가 다시 적용됐다.

- 캐릭터 프레임이 실제 backing pixel보다 클 때 Canvas 고품질 축소 필터를 적용한다. 원본 크기와 확대에서는 기존 최근접 샘플링을 사용한다.
- 플레이어·원격 플레이어의 몸체, 마법사 공격, 방패 돌진에 공통 함수를 적용한다. 프레임 선택·좌표·피벗·크기·카메라·애니메이션 타이밍은 유지한다. 호출 후 Canvas 상태를 복원한다.
- 마법사의 기존 런타임 atlas 합성도 고품질 필터를 사용한다. 생성되는 atlas 크기는 2048×1280으로 같다.
- Canvas의 CSS `image-rendering`을 `auto`로 바꾼다. 이 최종 합성은 Canvas 전체에 적용되지만 몬스터·배경의 개별 draw 샘플링은 변경하지 않는다.
- DPR 상한, Canvas backing 크기, FPS 제한, 텍스처 원본과 리소스 manifest는 그대로다. 새 WebP·원화·이미지 파일을 만들거나 교체하지 않는다.

## 로컬 측정

Chromium에서 네 화면 조건 × 네 직업, 수정 전후 각각 16개를 확인했다. 캡처는 기기 DPR을 반영한 전체 화면과 Playwright의 실제 캐릭터 영역 캡처다.

| 조건 | 실제 채팅 글자 | 수정 후 좌측 글자 | backing 크기 | DPR |
| --- | --- | --- | --- | --- |
| PC 1280×800 | 12px | 9–12px | 1280×720 | 1 |
| PC 1440×900, DPR 2 | 12px | 9–12px | 2560×1440 | 2 |
| 모바일 세로 393×852, DPR 3 | 6.6px | 6.6px | 727×1576 | 1.85 |
| 모바일 가로 852×393, DPR 3 | 10px | 10px | 1576×727 | 1.85 |

Canvas backing 크기와 성능 프로필은 전후 16개 조건에서 모두 같았다. HP/MP 9자리 수와 긴 퀘스트도 확인했다. 확대 캡처를 비교해 얼굴·모자·머리카락·무기·방패의 형태가 유지되고 축소 외곽선이 정돈되는 것을 확인했다.

32개 캐릭터 그리기 부하를 합성하고 raster 완료를 기다린 시간의 p95는 다음과 같다. 각 화면의 네 직업 중 최대값이며, 10회 준비 후 20회 측정했다.

| 조건 | 수정 전 최대 p95 | 수정 후 최대 p95 |
| --- | --- | --- |
| PC | 4.3ms | 7.3ms |
| 고해상도 PC | 7.4ms | 14.9ms |
| 모바일 세로 에뮬레이션 | 3.8ms | 15.0ms |
| 모바일 가로 에뮬레이션 | 3.0ms | 12.3ms |

필터에는 추가 비용이 있다. 이 수치는 클라우드 Chromium의 합성 렌더링 부하이며 실제 휴대폰의 FPS·발열·배터리·GPU 메모리를 입증하지 않는다. 실제 기기에서 움직임과 장시간 플레이를 확인하는 것은 남아 있다. backing pixel 수는 늘리지 않았다.
