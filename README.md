Yurika Online은 HTML5 Canvas와 Firebase를 기반으로 만든 실시간 웹 MMORPG입니다. 로그인, 캐릭터 성장, 튜토리얼, 멀티플레이어 동기화, 전투 UI를 한 프로젝트 안에서 다루고 있습니다.

현재 버전: **0.01.52**

## 핵심 기능

- 실시간 멀티플레이어: Firebase Realtime Database 기반 위치, 상태, 전투 동기화
- 전투 시스템: 체인 라이트닝, 매직 미사일, 파이어볼, 앱솔루트 베리어
- 성장 시스템: 레벨, 스탯, 스킬 강화, 인벤토리, 퀘스트 보상
- 온보딩: 프롤로그와 단계형 기본 튜토리얼
- 반응형 UI: PC, 모바일 세로, 모바일 가로 레이아웃 분기
- 배포 안정화: 서비스 워커와 버전 기반 캐시 무효화

- 모바일 파이어볼 조준은 터치 시작 순간의 바라보는 방향을 초기값으로 잡고, 손가락을 움직일 때만 조준선과 발사 지점이 갱신되도록 맞췄습니다.
- PC 모드에서는 기존처럼 파이어볼 입력 시 즉시 발사되는 흐름을 유지하도록 되돌렸습니다.

### 0.01.49

- 파이어볼 조준선이 홀드 중 이동 입력에도 반응하도록 보정해서, 방향키나 조이스틱으로 바라보는 방향을 바꾸면 조준선도 같이 회전하도록 맞췄습니다.
- 파이어볼 조준 시작 직후 기본 방향은 항상 현재 바라보는 방향 기준으로 잡히도록 유지하고, 드래그 조준이 없을 때는 이동 방향 변화가 그대로 초기 조준 방향을 갱신하도록 정리했습니다.

### 0.01.48

- 파이어볼 조준 중에는 스킬 버튼을 누른 채 손가락이나 포인터를 움직여 조준 위치를 계속 바꿀 수 있게 했습니다.
- 드래그 좌표를 월드 좌표로 환산해 조준 가이드와 실제 발사 지점에 반영하도록 연결해서, 모바일에서도 더 자연스럽게 조준 후 발사할 수 있게 했습니다.

### 0.01.47

- 조준 가이드는 현재 바라보는 방향을 기준으로 파이어볼 진행 폭과 최대 사거리, 끝 지점 폭발 반경까지 함께 보여주도록 넣었습니다.
- 원격 플레이어가 사용하는 파이어볼도 같은 목표 지점을 기준으로 시각화되도록 맞춰서 멀티플레이 화면에서도 투사체 방향이 덜 어색하게 보이도록 정리했습니다.

### 0.01.46

- 자동 일반공격이 임시로 잡은 타겟까지 수동 타겟처럼 빨간 원 마커를 띄우던 문제를 정리했습니다.
- 자동 타겟과 수동/튜토리얼 타겟을 분리해서, 자동공격은 정상 동작하되 어색한 빨간 타겟 표시만 더 이상 나오지 않도록 개선했습니다.

### 0.01.45

- 상태창에서 개발자 모드를 켰을 때의 동작을 다시 이전 흐름으로 맞춰, 검은 배경의 녹색 개발자 HUD가 월드 화면에 뜨고 상태창에서는 초기화 버튼만 토글되도록 복구했습니다.
- 플레이 화면 개발자 HUD에서 이름→UID 검색 UI는 제거해, 개발자 수치만 보이는 원래 형태에 가깝게 정리했습니다.
- `[Auto]` 버튼은 유지하되 미니맵 왼쪽 아래 위치를 유지하도록 배치만 정리했습니다.

### 0.01.44

- 상태창 개발자 모드는 이전 방식으로 다시 돌려, 개발자 모드일 때 상태창에서는 초기화 버튼만 보이도록 복구했습니다.
- 이름→UID 검색 UI는 플레이 화면 개발자 오버레이로 되돌렸고, 미니맵 왼쪽의 투명 HUD 안에서 다시 사용할 수 있게 정리했습니다.
- `[Auto]` 버튼은 미니맵의 왼쪽 아래 쪽으로 다시 옮겨, 공격 버튼과 상단 우측 아이콘 영역을 가리지 않도록 조정했습니다.

### 0.01.43

- 상태창에 잠깐 들어갔던 개발자용 검색/표시 UI는 원복해, 일반 플레이 상태창에서는 개발자 요소가 보이지 않도록 정리했습니다.
- 투명 개발자 HUD는 다시 월드 화면 전용으로 유지하면서, 미니맵 바로 왼쪽에 붙어 나오도록 위치를 조정했습니다.
- `[Auto]` 버튼은 공격 버튼과 상단 상태/가방 아이콘을 가리지 않도록 우측 HUD 사이의 빈 공간으로 다시 이동시켰습니다.

### 0.01.42

- 개발자 모드 오버레이를 맵 왼쪽의 얇은 텍스트 HUD로 줄여서, 켜 둬도 전투 화면을 크게 가리지 않도록 정리했습니다.
- 개발자용 이름→UID 검색은 더 이상 오버레이에 두지 않고 상태창 안에서만 보이게 옮겼고, 개발자 모드가 켜진 상태에서만 노출되도록 정리했습니다.
- 자동 일반공격은 사거리 안의 유효 타겟을 스스로 다시 잡아 실제로 동작하도록 보완했고, 토글 버튼은 `[Auto]` 고정 문구에 `비활성 회색 / 활성 녹색`으로 바꾸고 공격 버튼을 가리지 않는 위치로 재배치했습니다.
- 공격속도는 최대 `2.0`으로 고정했고, 체인 라이트닝 일반공격 틱은 기존 대비 약 15% 느리게 조정했습니다. 상태창 파생 공격속도와 스킬 상세 모달의 틱 간격 계산도 같은 규칙으로 맞췄습니다.

### 0.01.36

- 모바일 성능 telemetry를 추가해 update/render 시간, RTDB write 수, 추정 전송량, HUD 및 미니맵 갱신 빈도를 개발 오버레이에서 바로 확인할 수 있게 했습니다.
- 플레이어 presence와 zone 동기화 경로를 정리해 heartbeat와 zone profile payload를 더 가볍게 만들고, profile 저장/동기화 write를 집계 가능한 구조로 정리했습니다.
- 몬스터 상태 전송을 batch update 기반으로 묶고, 원격 플레이어는 오프스크린일 때 저주기 업데이트를 사용하도록 바꿔 모바일 CPU 사용량과 패킷 수를 함께 줄였습니다.
- HUD cooldown 갱신 빈도와 개발 오버레이 갱신 빈도를 모바일 cadence에 맞게 조정하고, 미니맵/HUD/원격 플레이어 갱신 횟수도 telemetry에 포함했습니다.
- 서비스워커를 app shell / static asset 분리 전략으로 재구성해 문서는 network-first, 정적 자산은 cache-first로 처리하도록 바꿨습니다.

### 0.01.35

- 모바일 전반에 공통 thermal profile을 적용해 렌더/업데이트 FPS와 DPR을 기기 환경에 맞게 낮추고, 과도한 발열을 줄이는 1차 최적화를 반영했습니다.
- 게임 루프에 update FPS 제어와 backlog 컷오프를 추가해 프레임이 밀릴 때 CPU가 과도하게 따라잡기를 시도하지 않도록 조정했습니다.
- 이동 패킷과 heartbeat 간격을 적응형으로 바꾸고, 최근 네트워크 송신이 있으면 중복 heartbeat를 생략하도록 조정해 패킷 사용량을 줄였습니다.
- 플레이어 profile 저장에 debounce/flush 흐름을 도입해 짧은 시간에 연속으로 발생하는 전체 저장 요청을 병합하도록 개선했습니다.
- 모바일 성능 모드에서는 몬스터 동기화 주기와 위치 변경 임계값을 완화해 호스트 write 빈도를 낮추도록 조정했습니다.

## 실행 방법

이 프로젝트는 정적 웹 서버로 실행하면 됩니다. `live-server` 기준으로 점검했고, Windows PowerShell에서 `npx live-server --port=8080`처럼 실행하면 환경에 따라 `listen EACCES: permission denied 0.0.0.0:8080`가 날 수 있습니다.

원인:

- `8080` 포트가 로컬 환경에서 막혀 있거나 다른 정책에 걸릴 수 있습니다.
- `live-server`가 기본적으로 `0.0.0.0`에 바인딩하려고 해서, Windows 환경에서 더 까다롭게 막히는 경우가 있습니다.

권장 기준:

- 같은 PC에서만 실행할 때는 `127.0.0.1`
- 기본 포트는 `8081` 또는 `5500`
- 가장 쉬운 방법은 `npm start`

### Windows PowerShell

프로젝트 루트에서:

```powershell
npm start
```

브라우저에서 접속:

```text
http://127.0.0.1:8081
```

수동 실행이 필요하면:

```powershell
npx -y live-server . --host=127.0.0.1 --port=8081 --no-browser
```

`8081`이 이미 사용 중이면:

```powershell
npx -y live-server . --host=127.0.0.1 --port=5500 --no-browser
```

### Windows CMD

프로젝트 루트에서:

```cmd
npm start
```

수동 실행:

```cmd
npx -y live-server . --host=127.0.0.1 --port=8081 --no-browser
```

### macOS / Linux

프로젝트 루트에서:

```bash
npm start
```

수동 실행:

```bash
npx -y live-server . --host=127.0.0.1 --port=8081 --no-browser
```

포트를 바꾸고 싶다면:

```bash
npx -y live-server . --host=127.0.0.1 --port=5500 --no-browser
```

### WSL

WSL에서도 같은 방식으로 실행하면 됩니다.

```bash
npm start
```

또는:

```bash
npx -y live-server . --host=127.0.0.1 --port=8081 --no-browser
```

Windows 브라우저에서는 보통 아래 주소로 접속하면 됩니다.

```text
http://127.0.0.1:8081
```

### 실기기 확인

휴대폰이나 태블릿에서 확인할 때는 로컬 LAN 서버 대신 Firebase 배포 주소를 사용합니다.

- 로컬 실행 방법은 개발 PC에서 브라우저로 확인하는 용도입니다.
- 모바일 실기기 확인은 배포 후 서비스 링크로 접속하는 흐름을 기준으로 합니다.
- 이 README에서는 휴대폰용 로컬 서버 실행 방법은 안내하지 않습니다.

## 버전 관리

- `version.txt`를 단일 버전 기준으로 사용합니다.
- 커밋 전 `.githooks/pre-commit`에서 `scripts/sync-version.js`가 실행됩니다.
- 이 스크립트는 `version.txt`, `src/js/main.js`, `src/js/world/scenes/LoginScene.js`, `index.html`, `sw.js`, `README.md`를 같은 버전으로 맞춥니다.
- `index.html`의 서비스 워커, CSS, 메인 모듈 쿼리스트링도 같은 버전으로 동기화합니다.

## 개발 메모

- 로컬 로그 파일 `live-server.log`, `live-server.err.log`는 커밋 대상이 아닙니다.
- 배포 후 캐시가 남아 있으면 `version.txt` 기준으로 새로고침이 유도됩니다.
- 사용자에게 보이는 문자열은 UTF-8 기준으로 유지해야 합니다.
